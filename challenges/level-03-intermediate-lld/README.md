# Chapter 3 — Intermediate LLD

**Goal:** keep a design correct as state, rules, and interactions multiply.

**Concepts:** state machines · concurrency basics · scheduling · rate limiting · resource
allocation · invariants under change.

**Example challenges (not yet written):** parking lot · elevator · library system · food
ordering · inventory · ride booking · rate limiter · task scheduler.

**You practice:** managing changing states, enforcing rules, and reasoning about
interactions between several objects.

**Move on when:** your design stays correct as behaviors and rules multiply, and you can
explain the trade-offs of your structure.
