# Chapter 2 — SOLID & basic LLD

**Goal:** introduce an abstraction **only when a real change demands it**.

**Concepts:** SOLID (in practice, not slogans) · dependency direction · strategy ·
polymorphism · seams for testability.

**You practice:** naming the exact change a design must absorb *before* choosing a structure
— and refusing to add structure when there is no such change.

**Move on when:** you can name the concrete change a new abstraction protects against, and
you can choose *not* to add one when there is none.
