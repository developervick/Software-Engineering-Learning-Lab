# 02 — SOLID

**Goal:** practice each principle **alone** until you can spot and fix its violation.

One file per principle. Do them in order — each reuses the previous.

| # | Principle | Gate |
|---|-----------|------|
| 1 | [SRP — Single Responsibility](01-srp.md) | ☐ |
| 2 | [OCP — Open/Closed](02-ocp.md) | ☐ |
| 3 | [LSP — Liskov Substitution](03-lsp.md) | ☐ |
| 4 | [ISP — Interface Segregation](04-isp.md) | ☐ |
| 5 | [DIP — Dependency Inversion](05-dip.md) | ☐ |

**Move on to [`03-design-patterns/`](../03-design-patterns/) when:** given a small messy
class you can name which principle it violates, fix it, and explain *why* your fix doesn't
violate the others.

> SOLID principles are not goals. They are signals that help you keep a design changeable.
> Over-applying them creates as much damage as ignoring them.
