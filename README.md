# Software Engineering Learning Lab

*A self-paced, concept-first lab for becoming the engineer who can **direct, review, simplify,
debug, and replace** an AI's work — not merely use it.*

## What this is

This repository is a **book you work through by writing code**. It is deliberately **separate
from my production project (Zapbite)**.

It is built around one idea:

> A tiny 100-line project I fully understand and wrote myself is worth more here than a
> 5,000-line system generated by AI.

The goal is not to finish a syllabus. It is to move knowledge from *"I understand it when
someone explains it"* to *"I can independently recognize, design, implement, modify, debug,
test, and explain it."*

## Concept-first: learn alone, then combine

The lab has two halves, and the order matters:

```
ideas in isolation            gate passed?          ideas combined
──────────────────       ───────────────────       ─────────────────
curriculum/            ──▶ yes ──▶             ──▶ challenges/
(drill each concept)                               (build a solution)
```

1. **Concept drills** ([`curriculum/`](curriculum/)) — read the goal, do the drill **alone**,
   pass a **Done-when gate**. The file **never** contains the solution.
2. **Challenges** ([`challenges/`](challenges/)) — only after the gates are met, you **combine**
   several concepts into one working solution.

You can't reliably combine things you've never built alone — that is why the order is fixed.

## The two goals — never mix them

| | **Zapbite** | **This lab** |
|---|---|---|
| Purpose | production | training |
| Speed | move fast | go slow |
| AI | use it freely | often avoid it on purpose |
| Success | shipped features | understanding |

The full reasoning behind this repository — and how AI should behave inside it — lives in
[`prompts/first-prompt.md`](prompts/first-prompt.md).

## How it works

**The concept loop** (Stages 1–4):

```
read the Goal → do the Drill ALONE → pass the Done-when gate
→ record the reflection → mark it in progress/concept-tracker.md
```

**The challenge loop** (Stages 5–6):

```
restate requirements → state assumptions → identify invariants → design →
implement → test → debug → refactor → explain → get a review
```

**The AI assistance ladder** — AI only *after* your own attempt, and only as far as you ask:

| Level | You get |
|---|---|
| 0 | The problem only *(default)* |
| 1 | A clarifying question |
| 2 | A small conceptual hint |
| 3 | A direction / design consideration |
| 4 | A review of your design or code |
| 5 | A partial solution (only the concept you're stuck on) |
| 6 | The complete solution (only when you explicitly ask) |

Full rules: [`docs/how-to-use-this-repo.md`](docs/how-to-use-this-repo.md).

## Progress tracking

Progress is tracked by **capability**, not by number of tutorials finished:

- [`progress/concept-tracker.md`](progress/concept-tracker.md) — every concept × mastery status

- [`progress/gaps.md`](progress/gaps.md) — weak spots and a revisit queue

Update [`progress/README.md`](progress/README.md) so future-you always knows the next step.

## Using this repo with an AI

1. Give the AI [`prompts/first-prompt.md`](prompts/first-prompt.md) once, at the start.
2. Ask for the **problem only**, and attempt it yourself first.
3. When stuck, name the assistance level you want (hint → direction → review → partial → full).
4. After you finish, ask for the standard review — correctness · design · simplicity ·
   extensibility · testability · maintainability · judgment · learning.
